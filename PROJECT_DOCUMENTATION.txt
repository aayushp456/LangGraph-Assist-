# 📚 Complete Project Documentation - AI Support Agent System

## 🎯 **Project Overview**

**Support Agent** is an AI-powered customer support ticket management system that uses advanced machine learning to automatically categorize, analyze, and suggest solutions for customer support tickets. The system combines semantic search, natural language processing, and decision intelligence to help support agents work more efficiently.

### **Service Layer** (`backend/services/`)

#### **1. Google Gemini Provider** (`gemini_provider.py`)
- **Purpose**: Primary AI provider using Google's Gemini models
- **Capabilities**:
  - Text generation (gemini-pro)
  - Embeddings (text-embedding-004)
  - Structured output with JSON mode
  - Automatic fallback to OpenRouter
- **Methods**:
  - `generate()` - Generate text responses
  - `embed_text()` - Create embeddings
  - `generate_structured()` - JSON output

#### **2. Enhanced RAG Pipeline** (`enhanced_rag.py`)
- **Purpose**: Advanced retrieval-augmented generation
- **Features**:
  - Multi-stage retrieval (dense + sparse)
  - Query understanding and expansion
  - Reranking with BM25
  - Metadata filtering
  - Grounded generation with evidence
  - Confidence scoring
  - Retrieval logging
- **Pipeline**:
  1. Query understanding
  2. Dense retrieval (FAISS)
  3. Sparse retrieval (BM25)
  4. Hybrid reranking
  5. Context building
  6. Grounded generation
  7. Evidence assessment

#### **3. Decision Engine** (`decision_engine.py`)
- **Purpose**: Make actionable decisions on tickets
- **Actions**:
  - `auto_resolve` - High confidence, simple issue
  - `escalate` - Complex, urgent, or low confidence
  - `agent_review` - Medium confidence
  - `request_info` - Missing information
- **Scoring**:
  - Analyzes routing confidence
  - Considers sentiment
  - Evaluates solution quality
  - Checks urgency indicators
- **Output**:
  - Recommended action
  - Confidence score
  - Reasoning
  - Next steps

#### **4. Document Chunker** (`chunker.py`)
- **Purpose**: Split documents for embedding
- **Features**:
  - Configurable chunk size (default: 500 chars)
  - Overlap management (default: 50 chars)
  - Metadata preservation
  - Chunk indexing
- **Use Cases**:
  - Knowledge base indexing
  - Long document processing
  - Context window optimization

#### **5. Sentiment Service** (`sentiment.py`)
- **Purpose**: Analyze emotional tone
- **Output**:
  - Sentiment label (positive, neutral, negative)
  - Confidence score
  - Tone indicators
- **Use Cases**:
  - Priority queue scoring
  - Escalation triggers
  - Customer satisfaction tracking

#### **6. Summarizer Service** (`summarizer.py`)
- **Purpose**: Create concise summaries
- **Features**:
  - Extractive summarization
  - Key point extraction
  - Configurable length
- **Use Cases**:
  - Ticket summaries
  - Quick overviews
  - Dashboard displays

#### **7. Solution Service** (`solution.py`)
- **Purpose**: Generate customer responses
- **Output**:
  - Draft reply text
  - Resolution steps
  - Confidence score
  - Relevant KB articles
- **Features**:
  - Context-aware generation

#### **8. Routing Service** (`rag.py`)

#### **9. FAISS Vector Store** (`faiss_store.py`)

## ✨ **Key Features**

### **1. AI-Powered Ticket Analysis**
- **Automatic Categorization**: Routes tickets to FAQ, BILLING, TECHNICAL, or ESCALATE
- **Sentiment Analysis**: Detects positive, neutral, or negative customer emotions
- **Smart Summarization**: Creates concise ticket summaries
- **Solution Generation**: Provides draft replies and resolution steps
- **Confidence Scoring**: Indicates reliability of AI suggestions

### **2. Knowledge Base Management**
- **Document Indexing**: Upload and index support articles
- **Semantic Search**: Find relevant content using meaning, not just keywords
- **File Upload**: Support for JSON, TXT, CSV files
- **Bulk Operations**: Index multiple documents at once
- **Category Organization**: Organize by FAQ, BILLING, TECHNICAL, etc.

### **3. Priority Queue System**
- **Smart Scoring**: Automatically prioritizes urgent tickets
- **Scoring Criteria**:
  - Escalated tickets: +100 points
  - Negative sentiment: +50 points
  - Low confidence: +30 points
  - New/unassigned: +20 points
- **Real-time Updates**: Queue refreshes automatically
- **Reason Display**: Shows why tickets are prioritized

### **4. Category-Based Workflow**
- **Triage Overview**: See all categories at a glance
- **Category Filtering**: Focus on specific ticket types
- **Status Filters**: Filter by new, in_progress, resolved, escalated
- **Search**: Quick text search within categories
- **Drill-down Navigation**: Category → Status → Ticket → Details

### **5. Real-time Updates**
- **WebSocket Events**: Instant notifications
- **Live Dashboard**: Auto-refresh without page reload
- **Event Types**: Ticket created, insights generated, stats updated
- **Broadcast System**: Updates all connected clients

### **6. Decision Intelligence**
- **Automated Decisions**: Recommends actions based on analysis
- **Action Types**:
  - Auto-resolve: High confidence, simple issues
  - Escalate: Complex or urgent issues
  - Agent review: Medium confidence
  - Request info: Missing details
- **Reasoning**: Explains why action is recommended
- **Next Steps**: Provides actionable guidance

### **7. Bulk Operations**
- **Bulk Ticket Ingestion**: Create multiple tickets at once
- **Bulk KB Indexing**: Index multiple documents
- **CSV Import**: Import historical ticket data
- **Batch Processing**: Efficient handling of large datasets

### **8. Analytics & Insights**
- **Triage Statistics**: Breakdown by category and status
- **Sentiment Tracking**: Monitor customer satisfaction
- **Confidence Metrics**: Track AI accuracy
- **Routing Accuracy**: Measure categorization performance
- **Retrieval Stats**: Analyze search effectiveness

## 🔄 **How It Works**

### **Complete Ticket Lifecycle**

#### **Phase 1: Ticket Creation**
```
Customer submits ticket
    ↓
POST /api/tickets/ingest
    ↓
Validate input data
    ↓
Create ticket in SQLite
    ↓
Trigger AI analysis pipeline
```

#### **Phase 2: AI Analysis**
```
Enhanced RAG Pipeline
    ↓
1. Query Understanding
   - Parse ticket text
   - Extract key information
   - Identify intent
    ↓
2. Multi-stage Retrieval
   - Dense search (FAISS embeddings)
   - Sparse search (BM25 keywords)
   - Hybrid reranking
    ↓
3. Context Building
   - Gather relevant KB articles
   - Extract evidence
   - Build context window
    ↓
4. AI Generation
   - Routing: Categorize ticket
   - Sentiment: Analyze tone
   - Summary: Create overview
   - Solution: Generate response
    ↓
5. Grounded Generation
   - Evidence-based answers
   - Citation tracking
   - Confidence scoring
```

#### **Phase 3: Decision Making**
```
Decision Engine Analysis
    ↓
Evaluate:
- Routing confidence
- Sentiment score
- Solution quality
- Urgency indicators
    ↓
Calculate priority score
    ↓
Recommend action:
- Auto-resolve (high confidence)
- Escalate (complex/urgent)
- Agent review (medium confidence)
- Request info (incomplete)
    ↓
Generate reasoning and next steps
```

#### **Phase 4: Data Storage**
```
Update SQLite Database
    ↓
Store:
- Ticket details
- Category and confidence
- Sentiment analysis
- AI-generated solution
- Decision recommendation
    ↓
Log:
- Routing decision
- Retrieval results
- Processing time
```

#### **Phase 5: Real-time Broadcast**
```
WebSocket Manager
    ↓
Emit events:
- ticket:created
- insight:generated
- solution:suggested
- triage:stats_updated
    ↓
Broadcast to all connected clients
    ↓
Frontend receives and updates UI
```

#### **Phase 6: Agent Interaction**
```
Agent views dashboard
    ↓
Checks priority queue
    ↓
Selects category (e.g., BILLING)
    ↓
Applies status filter (e.g., new)
    ↓
Clicks on ticket
    ↓
Reviews AI analysis:
- Summary
- Sentiment
- Suggested solution
- Recommended action
    ↓
Takes action:
- Resolve ticket
- Escalate to specialist
- Request more information
    ↓
System updates status
    ↓
WebSocket broadcasts update
    ↓
Dashboard refreshes automatically
```

## 🔍 **Knowledge Base Workflow**

### **Indexing Process**
```
1. Document Upload
   ↓
   POST /api/kb/index or /api/kb/index/file
   ↓
2. Document Chunking
   ↓
   - Split into 500-char chunks
   - Add 50-char overlap
   - Preserve metadata
   ↓
3. Embedding Generation
   ↓
   - Google Gemini embeddings
   - Convert text to vectors
   - Batch processing
   ↓
4. FAISS Indexing
   ↓
   - Store vectors
   - Build L2 index
   - Save metadata
   ↓
5. SQLite Storage
   ↓
   - Store in FAQ table
   - Add category tags
   - Enable text search
   ↓
6. Response
   ↓
   - Confirm success
   - Return chunk count
   - Provide stats
```

### **Search Process**
```
1. User Query
   ↓
   POST /api/kb/search
   ↓
2. Query Embedding
   ↓
   - Convert query to vector
   - Same model as indexing
   ↓
3. FAISS Search
   ↓
   - Find similar vectors
   - Calculate L2 distance
   - Return top-K matches
   ↓
4. Reranking (Optional)
   ↓
   - BM25 keyword scoring
   - Hybrid ranking
   - Boost relevance
   ↓
5. Filtering
   ↓
   - Apply category filter
   - Apply min score threshold
   - Sort by relevance
   ↓
6. Format Results
   ↓
   - Include text and metadata
   - Add similarity scores
   - Return JSON
```
